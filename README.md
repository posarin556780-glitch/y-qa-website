# เว็บไซต์ถามตอบ (Mobile-first)

เว็บไซต์ภาษาไทยสำหรับให้เจ้าของตั้งคำถาม และให้ผู้เข้าชมกรอกชื่อเล่นก่อนส่งคำตอบ และอ่านคำตอบของคนอื่นได้

## ไฟล์ในโปรเจกต์
- `index.html` — โครงหน้าเว็บไซต์
- `style.css` — รูปแบบที่ปรับตามหน้าจอมือถือ
- `app.js` — โหลดคำถาม/คำตอบและส่งคำตอบ
- `config.js` — ตั้งค่าการเชื่อมต่อ Supabase
- `supabase/setup.sql` — สร้างฐานข้อมูลและนโยบายสิทธิ์

## ขั้นตอน A: สร้างฐานข้อมูลฟรี
1. สมัคร/เข้าสู่ระบบที่ https://supabase.com/
2. สร้างโปรเจกต์ใหม่ และจดรหัสฐานข้อมูลไว้ในที่ปลอดภัย
3. เปิดเมนู **SQL Editor** ในแดชบอร์ด
4. เปิดไฟล์ `supabase/setup.sql` คัดลอกทั้งหมดไปวาง แล้วกด **Run**
5. ไปที่ **Project Settings → API** (ชื่อเมนูอาจต่างกันตามหน้าตาแดชบอร์ด)
6. คัดลอก **Project URL** และ **Publishable key** (โปรเจกต์เก่าอาจแสดง `anon` key)

## ขั้นตอน B: เชื่อมเว็บไซต์
1. เปิด `config.js`
2. แทนที่ `ใส่_PROJECT_URL_ที่นี่` ด้วย Project URL ของคุณ
3. แทนที่ `ใส่_PUBLISHABLE_KEY_ที่นี่` ด้วย Publishable key
4. บันทึกไฟล์

**ห้ามใส่ `service_role` key หรือ secret key ใน `config.js`** เพราะไฟล์นี้ถูกส่งให้ทุกคนที่เปิดเว็บดูได้ โปรเจกต์นี้ตั้ง Row Level Security (RLS) ให้ผู้ชมอ่านคำถามที่เผยแพร่แล้ว อ่านคำตอบ และส่งคำตอบเท่านั้น

## ขั้นตอน C: เพิ่ม/จัดการคำถาม
1. เปิด Supabase → **Table Editor** → ตาราง `questions`
2. กดเพิ่มแถว (Insert row)
3. ใส่ `title` (คำถาม), `description` (คำอธิบาย ถ้ามี), `is_published` = `true`
4. บันทึกแล้วรีเฟรชหน้าเว็บ คำถามจะปรากฏ
5. ดูคำตอบได้ในตาราง `answers`

หากต้องการซ่อนคำถาม ให้เปลี่ยน `is_published` เป็น `false` คำถามนั้นจะไม่ปรากฏต่อผู้เข้าชม แต่คำตอบเดิมยังอยู่ในฐานข้อมูล

## ขั้นตอน D: เผยแพร่ด้วย GitHub Pages ฟรี
1. สมัคร/เข้าสู่ระบบที่ https://github.com/
2. สร้าง repository ใหม่ ตั้งชื่อเช่น `my-qa-site` และเลือก **Public**
3. อัปโหลดไฟล์ `index.html`, `style.css`, `app.js`, `config.js` และโฟลเดอร์ `supabase`
4. เปิด repository → **Settings → Pages**
5. ในส่วน Build and deployment เลือก **Deploy from a branch**
6. เลือก branch `main` และ folder `/ (root)` แล้วกด Save
7. รอสักครู่ GitHub จะแสดง URL เว็บไซต์ในหน้า Pages

เมื่อมีการแก้ไฟล์แล้วอัปโหลดทับ เว็บไซต์จะอัปเดตตามนั้น

## ข้อควรรู้ก่อนแชร์
- คำตอบทั้งหมดเป็นสาธารณะ ใครเปิดเว็บก็อ่านได้ อย่าใช้กับข้อมูลลับหรือข้อมูลส่วนบุคคล
- ผู้เข้าชมไม่ต้องสมัครสมาชิก แต่ต้องกรอกชื่อเล่นและคำตอบก่อนส่ง และเวอร์ชันเริ่มต้นยังไม่มีระบบกันสแปมขั้นสูง
- อย่าเผยแพร่เว็บไซต์จนกว่าจะตั้งค่า `config.js` และทดสอบส่ง/อ่านคำตอบเรียบร้อย
- Publishable/anon key เปิดเผยได้เฉพาะเมื่อเปิด RLS และตั้งสิทธิ์อย่างเหมาะสมแล้ว ห้ามเปิดเผย service-role/secret key
- หากใช้ในวงกว้าง ควรเพิ่ม CAPTCHA, จำกัดอัตราการส่ง, ระบบรายงาน/ลบคำตอบ และระบบผู้ดูแลที่ปลอดภัย
- GitHub Pages ใช้เผยแพร่ไฟล์หน้าเว็บแบบ static; ฐานข้อมูลทำงานแยกผ่าน Supabase

## ทดสอบก่อนแชร์
- [ ] ใส่ค่า Supabase ใน `config.js`
- [ ] รัน `setup.sql` สำเร็จ
- [ ] เห็นคำถามตัวอย่างบนหน้าเว็บ
- [ ] ส่งคำตอบได้
- [ ] เปิดเว็บจากมือถืออีกเครื่องแล้วเห็นคำตอบเดียวกัน
- [ ] ตรวจสอบว่าคำตอบไม่มีข้อมูลส่วนตัว


## ถ้าเคยรัน SQL เวอร์ชันเก่าไปแล้ว
ไฟล์ `setup.sql` นี้เหมาะกับการติดตั้งโปรเจกต์ใหม่ หากสร้างตาราง `answers` ไปแล้วจากเวอร์ชันก่อน ให้รันคำสั่งนี้ใน SQL Editor เพื่อบังคับให้ชื่อเล่นเป็นข้อมูลที่ต้องกรอก:

```sql
alter table public.answers
  alter column display_name set not null;

alter table public.answers
  add constraint answers_display_name_length_check
  check (char_length(trim(display_name)) between 1 and 40);
```

ถ้ามีคำตอบเก่าที่ไม่มีชื่อเล่น คำสั่ง `set not null` อาจไม่ผ่าน ให้เติมชื่อเล่นให้แถวเก่าที่เป็นค่าว่างก่อน แล้วค่อยรันคำสั่งอีกครั้ง:

```sql
update public.answers
set display_name = 'ผู้ตอบเดิม'
where display_name is null or char_length(trim(display_name)) = 0;
```

อย่าเปิดเผยข้อมูลส่วนตัวในชื่อเล่นหรือคำตอบ และควรตรวจสอบนโยบายฐานข้อมูลก่อนเปิดให้สาธารณะใช้งานจริง


## ระบบแอดมินแยก (`admin.html`)

เว็บไซต์นี้เพิ่มหน้า `admin.html` สำหรับเจ้าของเว็บ เพื่อเพิ่ม แก้ไข เผยแพร่/ซ่อน และลบคำถาม ระบบแอดมินใช้ Supabase Auth และนโยบาย RLS ตรวจสอบสิทธิ์ที่ฐานข้อมูลด้วย

### ตั้งค่าระบบแอดมิน
1. ใน Supabase เปิด **Authentication → Users** แล้วเพิ่มผู้ใช้แอดมินด้วยอีเมลที่คุณควบคุม (ตั้งรหัสผ่านที่คาดเดายาก) หากเปิดการยืนยันอีเมล ให้ยืนยันก่อนเข้าสู่ระบบ
2. เปิด **SQL Editor** แล้วรัน `supabase/admin-policies.sql` หลังจากรัน `supabase/setup.sql` แล้ว
3. กำหนดสิทธิ์แอดมินใน `app_metadata` ของผู้ใช้นั้นให้มี `role: "admin"` จากฝั่งผู้ดูแลโปรเจกต์เท่านั้น โดยใช้ Supabase Dashboard/API ฝั่งเซิร์ฟเวอร์ที่เชื่อถือได้ หรือเครื่องมือจัดการผู้ใช้ที่มีสิทธิ์สูง ห้ามใช้ client-side code หรือให้ผู้ใช้แก้ `user_metadata` เพื่อกำหนดสิทธิ์เอง
4. เปิด `admin.html` ผ่าน URL ของเว็บ เช่น `https://ชื่อผู้ใช้.github.io/ชื่อ-repo/admin.html`
5. เข้าสู่ระบบด้วยบัญชีแอดมิน แล้วเพิ่ม/แก้ไขคำถามได้

**สำคัญ:** `admin-policies.sql` ใช้ `auth.jwt() -> 'app_metadata' ->> 'role' = 'admin'` เป็นตัวตัดสินสิทธิ์ในฐานข้อมูล หากยังไม่ได้กำหนด role ใน `app_metadata` จะไม่มีสิทธิ์จัดการคำถาม แม้เข้าสู่ระบบสำเร็จ

### วิธีที่ปลอดภัยในการกำหนด role
- ทำผ่าน Supabase Dashboard ที่รองรับการแก้ `app_metadata` หรือผ่านระบบฝั่งเซิร์ฟเวอร์ที่ใช้ Secret/service-role key ซึ่งเก็บเป็นความลับเท่านั้น
- อย่าใส่ Secret/service-role key ใน `config.js`, HTML, JavaScript ฝั่งเบราว์เซอร์, GitHub repository หรือส่งให้ผู้อื่น
- หากหน้า Dashboard ไม่มีช่องแก้ `app_metadata` ให้ใช้วิธีฝั่งเซิร์ฟเวอร์ที่ปลอดภัยหรือเครื่องมือจัดการผู้ใช้ที่เชื่อถือได้ อย่าทำ endpoint สาธารณะเพื่อเปลี่ยน role

### ข้อจำกัด/คำแนะนำ
- หน้าแอดมินนี้จัดการคำถามเท่านั้น ยังไม่มีหน้าจัดการ/ลบคำตอบในแอดมิน
- การลบคำถามจะลบคำตอบที่ผูกกับคำถามนั้นด้วย เพราะตั้ง foreign key `on delete cascade`
- ผู้ตอบทุกคนยังส่งคำตอบแบบสาธารณะได้โดยไม่ต้องล็อกอิน และคำตอบที่ส่งจะมองเห็นได้สาธารณะ
- ก่อนใช้งานจริงในวงกว้าง ควรเพิ่ม CAPTCHA/การจำกัดอัตราส่งคำตอบ และแนวทางรายงานเนื้อหาไม่เหมาะสม
